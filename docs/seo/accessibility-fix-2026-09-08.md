# Исправление замечаний доступности от 08.09.2026

Основание: [исходный аудит](performance-2026-09-08.md), узлы из `/tmp/clod-lighthouse-after.json` и повторного `/tmp/clod-lighthouse-followup-before.json`. Работа относится к представлению: цвета, доступные имена ссылок и уровни заголовков. Медицинские тексты, маршруты и обработчики записи не изменены.

## Причины и исправления

- В `global.css` уже существовал контрастный `--text-muted: #465550`, но Tailwind `clay.muted` обходил его и возвращал `#6B7280`. Теперь `text-clay-muted` использует существующий токен.
- Брендовые `--accent`, `--color-mint` и RGB-значение остаются `#1C89A1` / `28 137 161`. Для текста введён `--accent-ink: #166B7E` и его RGB-форма, для основных кнопок — `--accent-fill: #18768B`; `--accent-hover` остаётся `#166B7E`. Правила Tailwind `textColor` изменяют цвет текста, сохраняя фоновые и декоративные mint-утилиты. Прозрачные варианты текста продолжают генерироваться.
- `.text-accent`, `.badge-specialty-mint` и `text-clay-mint` используют контрастный текст. Это исправляет описания направлений, ссылки отзывов и бейдж «Запись онлайн». Основные кнопки, их малый вариант и `.btn-specialty-mint` используют контрастный фон.
- Контур клавиатурного фокуса стал непрозрачным `#1C89A1`, сохранив фирменный оттенок, толщину и отступ.
- `ServicesSection` больше не заменяет полную видимую подпись ссылки названием направления через `aria-label`. Имя формируется из видимых заголовка, описаний и «Перейти».
- `StarRating` формирует имя из видимой оценки и числа отзывов; скрытый текст добавляет «— рейтинг на ПроДокторов». Явные пробелы между текстовыми узлами сохраняют имя `5.0 (37) — рейтинг на ПроДокторов`. Для ссылки только со звёздами скрытый текст сообщает оценку из пяти; декоративные SVG скрыты от accessibility tree.
- Footer получил скрытый H2 «Информация о клинике», а восемь прежних H4 стали H3. «ВАБ как щадящая технология» больше не пропускает уровень. Визуальные классы заголовков сохранены.
- Четыре проверки направлений в `e2e/home.spec.js` адаптированы к полным доступным именам ссылок.

## Расчёт контраста

Порог обычного текста — 4,5:1, видимых частей элементов управления — 3:1. Источники: [W3C: контраст текста](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [W3C: нетекстовый контраст](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

Для каждого sRGB-канала `c = channel / 255`: `linear(c) = c / 12.92` при `c ≤ 0.04045`, иначе `((c + 0.055) / 1.055)^2.4`. Относительная яркость `L = 0.2126R + 0.7152G + 0.0722B`; контраст `C = (max(L1, L2) + 0.05) / (min(L1, L2) + 0.05)`. Для прозрачного цвета сначала выполняется смешивание каналов `foreground × alpha + background × (1 − alpha)`. Тест сравнивает неокруглённое значение с порогом; таблица округлена до сотых.

## Регрессия disabled-hover, обнаруженная CI

После первой публикации `199d856` CI обнаружил два падения в `e2e/booking-layout.spec.js:253` и `:262` (144 E2E прошли). У отключённых основных кнопок записи менялся только фон при наведении: обычное состояние уже использовало `--accent-fill: #18768B`, а более специфичная группа `.booking-primary-action:disabled:hover`, `.booking-submit:disabled:hover`, `.booking-result-action:disabled:hover` сохраняла прежний `--accent: #1C89A1`. Атрибут `disabled`, курсор и прозрачность работали; это была визуальная регрессия моей первой правки цветов.

Исправлена одна декларация этой группы: фон использует тот же `--accent-fill`, что и обычная кнопка. В `accessible-colors.test.js` добавлено сравнение RGB-фона до/после наведения для всех трёх селекторов. Red воспроизвёл три несовпадения `[28, 137, 161]` / `[24, 118, 139]`; после правки целевой цветовой набор проходит 24 теста. Существующие E2E продолжают проверять фактические стили и все состояния кнопок в браузере; их повторный запуск выполняет основная задача.
